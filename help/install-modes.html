Loading the components

Loading is one <script> tag you add near the top of your page; after it, you can use tags like <sol-button> or <sol-menu> anywhere in your HTML.

The loader tag

Add it once, in the <head> of your page, before any other <script type="module">:

<script src="https://cdn.jsdelivr.net/npm/sol-components/web/sol-load.js"
        data-components="sol-basic sol-feed"></script>

data-components names the components (or bundles) you want: each token is a tag name like sol-feed, or a bundle name — sol-basic (the everyday UI, RDF-driven menus included), sol-pod-bundle (pod browsing), sol-form-bundle (the RDF editing stack).

There is no local/CDN switch: everything loads relative to wherever sol-load.js itself came from. Load it from the CDN and the components come from the CDN; host the package yourself (say at /node_modules/sol-components/) and point src there, and everything is served by you:

<script src="/node_modules/sol-components/web/sol-load.js"
        data-components="sol-basic sol-feed"></script>

Run your code when it's ready

If you have JavaScript that uses the components, wait for them to be ready first:

<script type="module">
  await window.solLoadReady;
  // your code here
</script>

Components can also be loaded on demand from code — window.solLoad('sol-calendar') returns a promise for the import.

Add a <sol-login> to the page and, once the user is signed in, the data components automatically use that sign-in — no wiring needed.

When to use the component-interop broker instead

The tag above is all a page of sol-components needs. The component-interop loader does the same job through a manifest, and adds what a multi-library page needs: mixing independently-authored component libraries, sharing capabilities between them (one sign-in, one RDF store), and attribute-driven capabilities that auto-load when an attribute like data-from-query or data-edit-shape appears — see Shared resources and Authoring components. If both loaders end up on one page, whichever ran first wins; sol-load steps aside when an import map is already present.

Once the components are loaded, see Common attributes for the options most of them share.
