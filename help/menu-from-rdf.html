Adding from-rdf to a menu

By default <sol-menu>, <sol-tabs> and <sol-dropdown-button> are declarative-only: you author their items as light-DOM children (see the per-component help). To build the same menu from an RDF document instead, switch on one opt-in capability — the menu-from-rdf add-on — and point a from-rdf attribute at a ui:Menu subject. The add-on is the only piece that pulls in rdflib; without it, from-rdf is inert (the component logs a one-line notice and renders nothing from RDF).

1 · Switch the capability on

Load the add-on alongside the component. Pick the form that matches how you already load components:

<!-- The loader: name the component family + the add-on; rdflib rides in -->
<script src="https://cdn.jsdelivr.net/npm/sol-components/web/sol-load.js"
        data-components="sol-basic"></script>

<!-- …or ESM: import the add-on once, anywhere -->
<script type="module">
  import 'sol-components/sol-menu.js';
  import 'sol-components/menu-from-rdf.js';   // ← activation
</script>

Importing menu-from-rdf once activates from-rdf for every member of the menu family on the page — sol-menu, sol-tabs and sol-dropdown-button alike — in any load order.

2 · Point from-rdf at a ui:Menu

The attribute is a URL with a fragment naming the root ui:Menu subject. The same RDF shape drives any member of the family — swap the tag, keep the document.

<sol-menu            from-rdf="menu.ttl#MainMenu"></sol-menu>
<sol-tabs            from-rdf="menu.ttl#MainMenu"></sol-tabs>
<sol-dropdown-button from-rdf="menu.ttl#MainMenu"></sol-dropdown-button>

3 · The ui:Menu shape

A ui:Menu has a ui:label and its members as schema:itemListElement triples — one positioned schema:ListItem wrapper per member (schema:item names the member, schema:position its order). Each member is a ui:Link (a URL to load), a ui:Component (a custom element — the tag derives from its module's filename), a ui:Command (a host command), or a nested ui:Menu (a submenu). Every kind carries the SAME single payload predicate, schema:url.

@prefix ui:     <http://www.w3.org/ns/ui#> .
@prefix schema: <http://schema.org/> .

<#MainMenu> a ui:Menu ; ui:label "Demo" ;
  schema:itemListOrder schema:ItemListOrderAscending ;
  schema:itemListElement <#MainMenu-New>, <#MainMenu-Open>, <#MainMenu-Tools> .

<#MainMenu-New>   a schema:ListItem ; schema:item <#New>   ; schema:position 1 .
<#MainMenu-Open>  a schema:ListItem ; schema:item <#Open>  ; schema:position 2 .
<#MainMenu-Tools> a schema:ListItem ; schema:item <#Tools> ; schema:position 3 .

# commands: schema:url is a fragment IRI; the hyphen-free fragment is the key
<#New>  a ui:Command ; ui:label "New"  ; schema:url <#newItem> .
<#Open> a ui:Command ; ui:label "Open" ; schema:url <#openItem> .

<#Tools> a ui:Menu ; ui:label "Tools" ;                          # submenu
  schema:itemListOrder schema:ItemListOrderAscending ;
  schema:itemListElement <#Tools-Export>, <#Tools-Settings> .

<#Tools-Export>   a schema:ListItem ; schema:item <#Export>   ; schema:position 1 .
<#Tools-Settings> a schema:ListItem ; schema:item <#Settings> ; schema:position 2 .

<#Export> a ui:Command ; ui:label "Export" ; schema:url <#export> ;
  ui:attribute [ schema:name "format" ; schema:value "csv" ] .   # → params
<#Settings> a ui:Command ; ui:label "Settings" ; schema:url <#settings> .
TermOnMeaning
ui:labelany itemDisplay text.
schema:itemListElementui:Menu Membership — one triple per member. A curated menu points at schema:ListItem wrappers (schema:item + schema:position, sorted ascending); an unordered set points straight at the members.
ui:orientationui:Menu ui:Horizontal (default) or ui:Vertical.
schema:urlany leaf item The ONE payload: a Link's URL to open; a Component's ES module (its filename IS the element tag, e.g. sol-query.js → <sol-query>); a Command's registry fragment IRI (the hyphen-free fragment is the key — click → sol-command).
ui:contentsui:Link Literal HTML rendered inline (in place of a URL).
ui:attributecomponent / command schema:name/schema:value pairs — element attributes, or a command's params.
ui:iconany leaf itemIcon URL.

The canonical shape lives in shapes/menu.shacl. Its ui:Link / ui:Component / ui:Command shapes are shared: a menu item, a palette card, and a component-interop manifest entry are all the same shape (component-interop's manifest shape adds only the envelope and ci:module). A command's key is just a fragment name — no code is named in the RDF; your app maps the key to a handler when it receives the sol-command event.

4 · Reference-style menus (ui:Plugin entries)

The inline items above still work, but the richer form keeps every capability as ONE editable ui:Plugin entry in a catalog document, and makes menus ordered lists of references to those entries. The entry is at once the manifest, the palette card, and — when a menu references it — the mounted item; edit the entry and every consumer follows on the next parse.

@prefix ui:     <http://www.w3.org/ns/ui#> .
@prefix schema: <http://schema.org/> .
@prefix data:   <plugins-catalog.ttl#> .

<#Menu> a ui:Menu ; ui:label "Apps" ;
  schema:itemListOrder schema:ItemListOrderAscending ;
  schema:itemListElement <#Menu-Clock>, <#Menu-Penny>, <#Menu-Restart> .

# placement wrappers — position lives HERE, never on the shared entry
<#Menu-Clock>   a schema:ListItem ; schema:item data:Clock   ; schema:position 1 .
<#Menu-Penny>   a schema:ListItem ; schema:item data:Penny   ; schema:position 2 .
<#Menu-Restart> a schema:ListItem ; schema:item data:Restart ; schema:position 3 .

# …and in plugins-catalog.ttl — one entry per capability, ONE payload
# predicate (schema:url) the kind interprets:
<#Clock>   a ui:Plugin ; schema:additionalType ui:Component ;
  ui:label "Clock" ; schema:url <web/sol-clock.esm.js> .   # tag ← filename
<#Penny>   a ui:Plugin ; schema:additionalType ui:Link ;
  ui:label "Penny" ; schema:url <https://penny.vincenttunru.com/> .
<#Restart> a ui:Plugin ; schema:additionalType ui:Command ;
  ui:label "Restart" ; schema:url <commands.ttl#restartApp> .

The REQUIRED schema:additionalType picks the kind, and every kind carries the SAME single payload — schema:url — which the kind interprets: the URL a Link opens; the ES module defining a Component's element (the tag derives from the module filename); or, for a Command, a fragment IRI in the host app's command registry document whose hyphen-free fragment is the command key. :PluginShape in shapes/menu.shacl constrains the url per kind with sh:xone. Shared metadata rides on the entry: schema:description (card blurb), dcterms:publisher, dcterms:subject (topics), ui:icon, ui:attribute pairs, and settings pointers (dcterms:conformsTo / dcterms:references / schema:softwareHelp). <sol-menu>, the managers, and <sol-plugin-manager> resolve the references (across documents) automatically; serialization preserves whichever form a document already uses.
